R02  Return definition: return_s = 100 * (close_s / close_prev - 1), simple percent,
     close = last 1-min bar close of the session (bars END-stamped; session = 18:00 ET
     prev day -> 17:00 ET, label per runlib/session_boundary convention: hour >= 18
     rolls to next calendar day; 17:00 < t < 18:00 bars, if any, belong to the closing
     session... conservative: t <= 17:59 maps by the hour>=18 rule only). Returns between
     consecutive AVAILABLE sessions within a substrate. The first 2006 return may use the
     last 2005 session close (within deep substrate; the return itself is dated 2006,
     satisfying "returns 2006 ->"). Percent units used throughout (spec's power note is
     quoted in %/session).

R03  "session-clustered t": the session IS the clustering unit and the frame has exactly
     one return per session, so the cluster-robust t for mean(in)-mean(out) reduces to
     the two-sample Welch t: t = (mean_in - mean_out) / sqrt(s_in^2/n_in + s_out^2/n_out).
     This is what is computed and printed.

R04  Family for the max-|t| null = ALL ELEVEN preregistered statistics: TOM, FOMC_CYCLE,
     FOMC_DAY, CPI_DAY, NFP_DAY, OPEX_WEEK, DOW_Mon, DOW_Tue, DOW_Wed, DOW_Thu, DOW_Fri.
     (G3 says DOW rows face "the same family bar"; including them raises the bar for
     everyone — the conservative reading.) Per replication ONE shared circular shift of
     the return series is drawn; all 11 |t|'s are recomputed on the shifted returns
     against the FIXED calendar; max-|t| across the 11 forms the null draw. G1 pass:
     real |t| > 95th percentile of the max-|t| distribution (strict >).

R05  Null mechanics: session-level frame (one row per session), so a whole-session
     circular shift = rotation of the return vector along the session sequence by k,
     dummies fixed. 500 replications (spec floor), shifts drawn WITHOUT replacement,
     distinct, from {1..N-1}, numpy default_rng(seed=0). A sensitivity check (max-|t|
     statistic must move across probe shifts) runs before any percentile is quoted
     (null_guard doctrine).

R07  FOMC_CYCLE ("weeks 0/2/4/6 in Cieslak cycle time from each FOMC meeting start"):
     day counter runs in TRADING-SESSION units on the NQ session calendar (hard rule:
     session_id is the unit; Cieslak et al.'s business-day phase is approximated by the
     session sequence). Day 0 = the session whose label date equals the meeting start
     date (or the next available session if that date has no session). Day t>0 = t
     sessions after day 0 of the most recent meeting. Day -1 = the session immediately
     preceding the upcoming meeting's day 0 (upcoming-meeting assignment takes
     precedence over the trailing count). Even week w in {0,2,4,6} = cycle days
     {5w-1 .. 5w+3}. Dummy=1 on those days, 0 on other DEFINED cycle days. Sessions
     with UNDEFINED cycle position (before day -1 of the first 2006 meeting; the spec
     freezes the fetch at 2006, so the tail of the Dec-2005 cycle cannot be labeled)
     are EXCLUDED from the FOMC_CYCLE statistic entirely (neither in nor out) — they
     are not silently mislabeled as controls.

R08  TOM (McConnell-Xu): in-window = the LAST session of each calendar month (by session

     last session of 2026-07 qualifies (its following-month sessions are past the seal

R09  OPEX_WEEK: for every calendar month, third Friday F; in-window sessions = those
