R4  SESSION/WEEK GRID. date is the exchange-session label (18:00->17:00 ET,

R5  FORMATION (12-1). Per root, on the root's own session sequence. Let j index the
    root's most recent session at or before the rebalance date. F = cum[j-21] -
    cum[j-273], where cum = cumulative sum of ret_usd. Included: 252 sessions
    j-272..j-21; skipped: the 21 most recent sessions j-20..j (the rebalance session is
    one of the skipped 21). Valid iff the root has >= 274 sessions through j
    (j >= 273, 0-based).
    "Return" = the substrate's own economic return in USD (cumsum of ret_usd), the
    exact quantity TSMOM_V1 (research/multi_market/src/tsmom_v1.py, build()) uses for
    its horizon returns - the cited multi-market convention. No vol- or scale-
    normalization of the formation value: the spec names none, and inventing one would
    be an unfrozen transformation. Caveat recorded honestly: ranking raw USD returns
    across roots mixes contract dollar-vol scale into the rank; this is the literal
    frozen formulation and is carried as-is.

R6  PARTICIPATION ("valid formation") at a rebalance date t, per root:
      (a) the root's most recent session d_r <= t is within 7 calendar days of t
          (staleness rule; CARRY_V1 / VL_V1 precedent "traded in the last week"),
      (b) eligible == True on that session (the substrate's own tradability contract:

R7  SIGMA. Trailing 63-session std (ddof=1) of ret_usd on the root's own sessions
    ENDING AT AND INCLUDING the rebalance-decision session j. Decision is at the

R9  WEIGHTS. Per leg (6 roots): u_i = 1/sigma_i; share s_i = u_i / sum(u); cap
    s_i <- min(s_i, 3 * 1/6 = 0.5) in ONE deterministic pass, cap DOWN only, no
    redistribution (VL_V1 sector-cap precedent). Leg scale lambda solves the leg's
    daily USD vol under the LINEAR (perfect-correlation) risk-summation convention -
    the same budget-division convention TSMOM_V1/CARRY_V1 use:
    lambda * sum(s_i * sigma_i) = V_leg, with V_leg = 0.10 * C / sqrt(252) and
    NOTIONAL CAPITAL C = $1,000,000. Contracts n_i = +/- lambda * s_i (continuous,
    fractional - research convention, labelled as such). C and the linear-vs-sqrt
    summation choice are pure scale factors: every gate (sign of net, t, shares,
    percentile, halves) is invariant to them; C only sets reporting units.

R10 P&L ACCOUNTING ("fills at the next session's open"). Position n_k from rebalance k
    is in force from its per-root fill session f_k(r) open to the next fill session
    f_{k+1}(r) open. Holding-window USD return per root:
      H_k(r) = intraday_usd(f_k(r)) + sum ret_usd over sessions strictly between
               f_k(r) and f_{k+1}(r) + overnight_usd(f_{k+1}(r)),
    using the substrate's own overnight/intraday split (roll.py): the outgoing
    position earns the overnight into the fill open, the incoming position earns the
    intraday from the fill open. When no trade occurs at a boundary the split
    telescopes exactly to n * ret_usd. Weekly gross_k = sum_r n_k(r) * H_k(r),
    attributed to rebalance week k. The final holding window is truncated at the last
    loaded session (2018-12-31 boundary): its entry cost is charged, its post-boundary
    P&L and exit do not exist in this run (window isolation; no 2019 row is loaded).

R11 COSTS (turnover-based, documented before computation).
    Cost RATE per root: one-way (per side, per contract) = COMMISSION_RT/2 + ticks *
    tick_usd, with COMMISSION_RT = $4.36/ctrRT, ticks = 1 (PRIMARY) / 3 (STRESS),
    tick_usd = TICK[root] * point_value. So a full round trip costs 4.36 + 2*ticks*
    tick_usd - exactly TSMOM_V1's side_cost = spread_ticks*tick_usd + COMMISSION_RT/2
    ("the multi-market convention" the spec cites), and the spec's own words
    "1-tick spread PER SIDE".
    TURNOVER: at fill k, |n_k(r) - n_{k-1}(r)| contracts change = that many one-way
    fills (|weight change| -> 0.5 RT per contract-unit changed). First position is a
    pure entry (|n_0 - 0|).
    ROLLS: holding a contract across a roll IS a close+reopen (the substrate's
    economic return is defined by that self-financing switch), so each rolled session
    in a holding window charges 2 sides on the position carried into that session:
    rolls at sessions s with f_k(r) < s <= f_{k+1}(r)... assignment: a roll AT the
    fill session f_k(r) charges on |n_{k-1}| (the position entering that open); rolls
    strictly after f_k(r) and before f_{k+1}(r) charge on |n_k|; the roll at
    f_{k+1}(r) belongs to window k+1's fill-session rule. TSMOM_V1 precedent (roll
    cost on q_prev). A no-roll-cost figure is printed as a DIAGNOSTIC line only;
    the GATES use the roll-inclusive model (conservative, physically real).
    TICK TABLE: reused verbatim from runs/VOLUME_LIQUIDITY_V1_20260828/src/
    vl_primary.py (TICK dict, lines 56-59), which covers exactly the 21 CORE roots;
    point values from the parquet's own point_value column (= ncd_day.PV).
