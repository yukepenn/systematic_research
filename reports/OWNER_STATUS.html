Holiday early closes were never modelled — and this hit all three objects, including the "clean" ones

43 early-close sessions sit inside the dev window (~10/yr: 31 at 13:00 ET, 9 at 13:15, 2 Good Fridays at 09:15, and 2025-01-09's Day of Mourning at 09:30). The flatten was hardcoded to the normal clock, so on those days it never fired and only the 30-second engine backstop closed the position — about 14.5 minutes inside the margin window. The schedule is now session-relative, which on a normal close evaluates to exactly the old 16:30 and 16:39, leaving all 1,095 normal sessions unchanged by construction.

Why your own Strategy Analyzer shows 2026 in profit — both numbers are right

Two separate effects, and the second one surprised me.

Window. Every row above stops at the dev boundary, 2026-05-29. June–July 2026 alone is worth +$59,515 over 86 trades, and it is outside every table in this program. A UI run to 2026-08-07 additionally picks up an Aug 1–7 sliver (≈ +$11,083) that is locked-forward virgin data — I deliberately did not touch it.

Start state, which I had not accounted for. On the identical Jan→May window, the same object run fresh from 2026-01-01 returns +$7,426.36 over 174 trades, while the same window sliced out of the full 2022–2026 run returns −$46.60 over 185 trades. Same code, same end date, $7,473 and 11 trades apart. A run that begins on 2026-01-01 has no history: sigma460 warms up from scratch over ~460 bars, the tilt state needs 50 prior session closes, and B-MOM needs 14 RTH days of time-of-day history. For roughly the first quarter of a fresh run the strategy is operating on immature state.

So: every recency row above is a continuation number and will not reproduce in the Strategy Analyzer from a same-year start. Comparing a sliced year against a UI run started that January compares two different objects. This is also a third reason the retracted 2026 claim could not carry weight — that figure is not even invariant to how the backtest is started.
