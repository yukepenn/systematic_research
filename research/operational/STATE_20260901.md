## §2 WHAT WAS BUILT — `MX01`

The owner's constraint was capital: the live account holds ~$10.2k, which cannot carry
M_11 at 1 NQ + 1 NQ. The instruction was "same triggers, 3/10 size, execute with MNQ."

**The design decision that made it safe: separate the DECISION instrument from the EXECUTION
instrument.**

```
series 0   NQ  1-min   every signal, clock, threshold, quantile, accumulator.  UNTOUCHED.
series 1   MNQ 1-min   orders only.  Never read by a decision.
                       (XM: 0 NQ · 1 ES · 2 RTY · 3 YM · 4 MNQ)
```

The obvious alternative — attach the certified class straight to MNQ and rescale the dollar
inputs — was **rejected in the spec, before any result existed**. P1's cumulative delta and
volume normalisation come from the primary series' own volume, and the delta gate enters the
vote directly (`voteOK = nMemLong * nThr * (1 + dL) >= 16`). On MNQ's tape the decisions would
have drifted for a reason with nothing to do with the edge, by an amount nobody could bound.

Under the chosen architecture that drift is **zero by construction** — and the measurement
proves it rather than asserting it:

| gate | observed | |
|---|---|---|
| G1 source identity | P1 19/19 edits + 15/15 constants; XM 24/24 + 20/20, each matched exactly once | PASS |
| G2 compiles | 0 errors, 0 warnings, both classes | PASS |
| **G3 decision identity** | **byte-identical export, same `sha256`, 61,600 bars per leg** | **PASS** |
| G4 trade parity | 68 trades, 0 exceptions in 544 field comparisons | PASS |
| G5 quantity mapping | ratio exactly 3 on all 68 trades, both order legs | PASS |
| G6 backtest inertness | implied by G3 | PASS |

The repo's standing parity band is ≥99 % agreement. That is the right bar for two *independent*
implementations and the **wrong** bar here: the signal code is byte-identical and reads the same
bars, so anything short of exact equality would have meant a defect. The spec set it at exact
before the test ran.

### The one departure from the literal instruction

The owner said to scale the fixed dollar amounts by 3/10 as well (1300 → 390, 1000 → 300).
**They were not scaled, and the reason is arithmetic, recorded in the spec before results.**

The W98 session box accumulates **per contract** against the *primary's* PointValue and is never
multiplied by quantity, so 1300/1000 are already quantity-invariant thresholds of **−65.0 and
+50.0 index points**. Scaling them while PointValue stays 20 would put the halt at −195 points —
a box three times wider, which in practice stops firing. Making the position smaller while making
the risk box wider is the opposite of the intent. G3 confirms it: `sessPnl` and `stopped` are
among the byte-identical columns.

## §5 THREE DEFECTS THAT WOULD ONLY HAVE BITTEN IN LIVE

1. **The unindexed `Position` would have latched a permanent halt on the first MNQ fill.**
   `Position` is `BarsInProgress`-relative — confirmed from **IL**, not documentation — so inside
   `OnBarUpdate` at BIP 0 it reads the **NQ** strategy position, permanently flat once orders route
   to MNQ. `AssertLedgerMatchesStrategyPosition` would have fired `RECONCILE-BREAK` on the first
   entry. Fixed with explicit `Positions[EXEC]` / `Positions[MNQ]`.
2. **XM has a fourth, easily-missed order site** — the `HdDeadSeriesObserver` emergency flatten,
   textually identical to the alpha exit. Missed, it would have sent an un-ported order.
3. **Export handle collision.** Every P1 class writes `we_p1pct_<Tag>.csv`, opened with
   `append:false`. The second opener throws into a **silent** catch, sets `export = null`, and the
   leg then runs with **no ledger and no diagnostics while every health check reports green.**
   This actually occurred briefly when four MNQ strategies shared two filenames; removing the two
   paper validation legs cleared it.

Also caught, by a 25-line compile probe before a single line of real port existed: `Position` and
`Instrument` are **properties**, not usable as bare type names (CS0118).

## §7 THE CROSSTRADE DECISION

The MCP is a **remote** server — `https://app.crosstrade.io/v1/api/mcp`, verified in
`~/.claude.json`. Reading their own legal pages:

- ✅ They claim **no ownership** of and **no licence** over customer content. This is not an IP grab.
- ⚠️ Their Terms are **silent on any confidentiality obligation owed to the customer**.
- ⚠️ Liability capped at the greater of 12 months' fees or **$100**.
- ⚠️ Privacy Policy retains **"API request and response logs" for 90 days**; silent on source code.

So the exposure is *absence of contractual protection*, not evidence of misuse — a smaller thing
than it feels, but not nothing, and the fix is free. **`CLAUDE.md` §1 now bans sending strategy
source through it**; §6 carries the local path (`cp` into `bin/Custom/Strategies`, verify by
**resolving the class**, `sha256` the two copies; use a small synthetic **probe** for syntax
checks). `RunStrategyBacktest` stays allowed — it takes a class name, not source.

**Recorded, not hidden:** on 2026-08-31 the full source of both MNQ classes (~80 KB each) was sent
twice through `CompileNinjaScript`. Those logs age out around **2026-11-30**.
